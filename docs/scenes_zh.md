# 翻译场景

[English](scenes.md)

## 目标

识别会把专名听错（「インフィア」本该是ニンフィア，「メデオ」本该是メテオ），翻译模型也会把认对的专名按字面译错（「クラウド」译成「云」）。用户可以建「翻译场景」，比如「最终幻想7」「宝可梦」「药屋少女的呢喃」。每个场景有自己的描述、对照表、语言和字幕记录。翻译时只带上和这一句相关的对照条目。看完以后，用户可以在字幕记录上点「学习专名」，用自己接的 LLM 扫一遍，确认建议后加进场景，下次看就生效。

## 设计决定

| 项 | 决定 |
|---|---|
| 单位 | 场景。描述、对照表、语言、字幕记录都按场景分开 |
| 默认场景 | 「通用」，总在第一个。在它的记录上学习时，让用户选加到哪里：通用、某个现有场景，或新建一个场景 |
| 场景描述 | 随每句一起发给翻译模型，也给扫描用的 LLM 当背景；本机 2B 模型不发（它会把描述里的名字编进没提到它们的句子）。见[实验（2026-10-28）](#实验2026-10-28场景描述进翻译提示词) |
| 语言 | 场景绑定听到的语言和目标语言：切到场景就切语言，在场景里改语言也会存回场景 |
| 学习方式 | **不做边看边学**：观看时不弹任何提示，不打扰用户。用户在字幕记录上点「学习专名」才扫描，结果列成建议清单，默认全选，确认后加进场景，可以撤销。取消勾选的会记下来，以后不再建议 |
| 扫描分段 | 记录按每 120 秒或 60 句分段，一段一次请求 |
| 扫描用的 LLM | 用户自己接的 OpenAI 兼容接口（复用翻译里「自定义接口」那份列表，只列通用对话格式的），在学习对话框里选，记住上次的选择 |
| 重译 | 采用之后可以用新的对照表重译这些记录，结果写回字幕记录，用当前的翻译引擎 |
| 字幕记录 | 只存本地，默认关，用户自己打开。设置里有一页查看和管理 |

## 数据

### 场景

存在用户数据目录的 `scenes.json`，和设置分开（`internal/scene`）。

```go
type Scene struct {
	ID       string
	Name     string
	About    string // 描述：随每句发给翻译（2B 除外），也给学习专名的模型看
	Src, Tgt string // 语言，第一次使用前为 ""
	Terms    []Term
	Rejected []string // 用户没采用的建议（听到的写法），不再建议
}

type Term struct {
	Src   string   // 原文的正确写法：クラウド
	Tgt   string   // 译名：克劳德
	Heard []string // 识别听错的写法：メデオ（对应 メテオ）
	Auto  bool     // 学到的；手动加的为 false
	Added time.Time
}
```

`Prefs` 里相关的字段：`Scene`（当前场景的 ID，`""` 表示「通用」）、`History`（是否保存字幕记录，默认 false）、`Learn`（学习专名用哪个接口，上次选的）。

### 字幕记录

打开之后，每次观看存一个文件：`history/<场景 ID 或 general>/<开始时间>.jsonl`（`internal/history`）。第一行写场景 ID、当时的场景名、语言、开始时间和声音来源的应用名（全部声音时为空）；之后每行一句：时间、显示的原文、识别的原样（只在对照表改过时才有）、译文、出错原因。每句用到的对照条目不存，随时能按对照表重新算出来。

保存时机：

- 一句译完才存，严格按顺序，前一句没译完，后面的先等着。
- 停止时，没译完的按当时的样子存，没有译文就存草稿。
- 切换场景、重新开始（比如换了语言）会另起一个文件。
- 观看中途打开保存，屏幕上还在的句子也会存下来。
- 没有句子就不建文件。

关掉保存时不删除已有文件。删除时先把文件改名为 `.deleted`，所以可以撤销；下次启动后第一次打开列表时才真正删掉。列表和内容都在后台读。

## 翻译时怎么用对照表

- **只带相关条目**：一句话里出现了某个条目的原文写法或任一听错写法，才把这个条目带上，最多 `scene.MaxTerms` 条。
  - **匹配规则**：拉丁字母按整词匹配，不区分大小写，免得 `Eva` 匹配到 `evaluate`；其他文字先规范化再匹配（NFKC、全角半角、大小写、空格、「・」，Ⅶ 和 VII 视为相同）。
- **Index 格式**：在 `【约束要求】` 里加一条 `【硬性要求】专名/术语对照: メデオ→陨石、メテオ→陨石`，这是官方的 instTrans 写法。条目只带它命中的写法。
- **通用对话模型**：在系统提示末尾加一句 `Render these names as given: A → B; C → D.`
- **原文显示**：确认过的听错写法在提交时直接替换成正确写法，所以原文栏显示「メテオ」。只按字面替换，不做模糊匹配。未提交的原文和抢先翻译的草稿也一样。
- **场景描述**：Index 格式在对照表之后加一条 `【注意】背景：<描述>`（官方 instTrans 里用来消歧的软约束）；通用对话模型在系统提示里加 `What is being watched: <描述>.`。`translate.Request.About`、`live.Config.About` 和对照表一样由 core 提供、并发安全，改了描述或切场景，下一句就生效。本机 2B 不带（`models.Model.NoAbout`）。
- **实现**：`translate.Request.Terms`；`live.Config.Terms` 在提交时改写原文，翻译时按当前对照表取条目，由 core 提供、并发安全。学到新条目后不用重启会话，下一句就生效。切场景时换语言和对照表，只有语言变了才重启会话。

## 学习专名

- **入口**：设置的「字幕记录」页。可以对一次记录学习，也可以对筛选出来的全部记录学习（比如一个场景的所有记录）。不在观看时触发。
- **输入**：
  - 场景名和描述
  - 现有对照表，以及用户没采用过的建议（标明「不要再建议」）
  - 每段字幕里每句的「原文 + 当时的译文」
- **提示词**：见文末「附：扫描提示词」。只让 LLM 找确实出了问题的专名：听错的，或者原文对了但译错的。返回 `heard / src / tgt / sure`。
- **筛选规则**（`internal/learn`，来自实验）：
  - `sure` 为 true，并且 `heard` 能在这一段原文里按字面找到，才列为建议。
  - 只差大小写、空格、标点的丢掉。
  - `heard` 以 `src` 开头的（专名后面带了助词、词尾，比如 개미들→개미、엔터주로→엔터주），不替换原文，只当作译名条目。
  - 和手动条目同名的不列，手动条目优先。
  - 同一个专名在几段里都出现，合并成一条，听错写法合在一起，记下出现次数。
- **对话框**：选接口（没有就提示添加，添加接口的对话框直接在这页弹出；写清楚会把字幕文字发给它）→ 进度（「第 3 段 / 共 8 段」，可以取消）→ 建议清单（默认全选；听错的写法 → 正确写法 → 译名、句数和例句）→ 选「加到」哪个场景（也可以新建）→ 采用（可以撤销）→ 可选「用新对照表重译」。
- **失败**：某一段出错（接口错误、超时、额度用完、回复解析不了）就跳过，结束时说明有几段失败、最后一个原因，已经拿到的建议照常列出。
- **请求**：`translate.Endpoint.Chat`，普通的一问一答，沿用关闭思考、服务端不认参数时去掉重试的那套逻辑，超时 2 分钟。不依赖 `response_format`，从回复里截取 JSON。
- **重译**：只重译对照表命中的句子，其他句子不动；按对照表改写原文、带上条目重译，用当前的翻译引擎，写回文件。

## 以后再考虑

- 边看边学：扫描逻辑共用，只是输入换成实时的每 120 秒字幕；要等有数据说明长时间观看值得这么做。
- Apple 识别的置信度标记：实验里它只能当提示，要从引擎经过断句器一路传到句子上，改动较大，收益还没证明。
- 对照表的导入导出。

## 测试

- `scene`：匹配的边界情况（假名、拉丁词边界、规范化）、替换、存取。
- `learn`：筛选规则（只改格式的、带助词的、找不到字面的、手动条目同名的、没采用过的）和合并，用实验里的真实回复做测试数据。
- `translate`：提示词里带上了条目。
- `live`：一个只返回固定条目的 `Terms`，检查原文被替换、请求里带了条目。
- bench：`tomoru-bench -glossary <目录>`，目录里每个用例一个 `<用例>.json`（`[]scene.Term`），跑带对照表的对比。用实验学到的对照表跑雷军演讲和任天堂发布会：原文里的「刘北 / 刘备 / 刘伟」改成了纽北，「メデオ」改成了メテオ，「インフィア」改成了ニンフィア；译文从 Liu Bei 变成 Nürburgring，标题译成《最终幻想7 重生》。见译文 p50 0.93 → 0.96 秒，在波动范围内。

## 实验（2026-10-19）

- **数据**：bench 里专名多的 6 段，共约 27 分钟，用 Apple 本地识别。
- **翻译**：Index 云端。
- **扫描**：试了 qwen3.8-flash、deepseek-v4.1-flash、qwen3.8-max。
- **用户一句话生成初始对照表：变差多于变好**。表里只有约 10% 的词在视频里出现过。`iPhone→iPhone` 这类条目只会把句子改写一遍，强行套的译名还会丢书名号。所以场景描述起初只给扫描用；[2026-10-28 的实验](#实验2026-10-28场景描述进翻译提示词)之后也发给翻译。
- **每 90 秒扫描「原文 + 当前译文」：有效**。
  - 雷军演讲：「刘备 / 刘北」→ 纽北，「舒七」→ SU7，「Autra」→ Ultra
  - 任天堂发布会：《最终幻想7 重生》《塞尔达无双 灾厄启示录》
  - COTEN 播客：《我的奋斗》
- **模型差别大**：
  - qwen3.8-flash 自动纠错 7 次，比如「刘北」→「徕卡」
  - deepseek-v4.1-flash 不纠错，但漏得多
  - qwen3.8-max 最好
- **识别端加热词不可行**：Apple SpeechTranscriber 不认 `contextualStrings`，Qwen 实时识别没有热词字段，SenseVoice 没有热词。（2026-10-31 起，能接收提示的识别引擎会拿到场景里的名字：OpenAI、Qwen 云端的 `vocabulary`（3.1 模型现在有了）和 Qwen3-ASR；见[识别适配层](recognition_zh.md)的“提示”一节。）
- **Apple 的置信度**：大部分听错的词明显偏低（「基金」0.26、「占女」0.31），但「インフィア」错了却是 0.999。所以只能当提示，不能当闸门。
- **用量**：看一小时大约 6 万 token。

## 实验（2026-10-28）：场景描述进翻译提示词

10-19 的实验只试了用描述生成初始对照表，放进翻译提示词时只看到会编名字。这次直接对比带 / 不带描述。

- **数据**：bench 里名字多的 7 段（药屋 PV、任天堂直面会、Apple 发布会、雷军演讲、Running Man、Lex 播客、COTEN），约 31 分钟。描述像用户会写的那样一句话，比如「药屋少女的呢喃 第3季 PV，角色有猫猫、壬氏」「雷军 2025 年度演讲，讲小米 SU7 Ultra 跑纽北」（bench `-about <目录>`）。
- **只翻人工字幕**（`-mt-only`，chrF 只有有人工译文的 3 段）：

| 翻译 | 不带 | 带 | 看到的 |
|---|---|---|---|
| Index 云端 35B | 24.0 | 24.9 | 识别错的「刘北」译成 Nürburgring，《药屋少女的呢喃》标题译对，COTEN 里「お父さん」不再译成「我爸」；任天堂那段几只宝可梦的名字编得更离谱 |
| 本机 9B | 25.4 | 26.2 | 舒淇 → SU7、刘北 → Nürburgring、标题译对、NVIDIA → 英伟达；没看到编出来的名字 |
| 本机 2B | 23.3 | 24.0 | 编名字：「いなご（蝗虫）」译成「壬氏」，一句韩语开头凭空多出「刘在石：」 |

- **Apple 识别 + 云端**：chrF 21.8 → 23.1，见译文 p50 2.23 → 2.02 秒（波动）；雷军演讲 Nürburgring 0 → 3 次；Running Man 一句识别成乱码的话被译成「刘在石哥和池石镇哥的声音出来了」，可能猜对了。
- **结论**：云端、9B、用户自己接的接口带描述，2B 不带。

## 附：扫描提示词

`internal/learn` 用的系统提示词（实验第二轮的版本）。`{src}`、`{tgt}` 是语言名称。用户消息依次放：场景名和描述、现有对照表、每句的「原文：… / 译文：…」。

```
你帮实时字幕纠正专名。下面每行是语音识别出的{src}原文，和它当时的{tgt}译文。
只找出确实出了问题的专名（人名、角色名、作品名、地名、组织、产品名、专有术语）：
- 原文被识别成了同音、近音的错字：heard 写原文里的原样（只写专名本身，不带助词、词尾），src 写正确写法；
- 原文对了但译文把它译错了（例如把角色名按字面意思翻译）：heard 和 src 都写原样。
tgt 写通行的{tgt}译名（官方译名优先）。已经译对的不要写，普通词不要写，只差大小写、空格、标点的不要写。没把握就不要写，sure 表示你是否确信。
只输出 JSON：{"terms":[{"heard":"...","src":"...","tgt":"...","sure":true}]}
```
