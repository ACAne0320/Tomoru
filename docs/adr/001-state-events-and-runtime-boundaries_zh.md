# ADR 001：状态命令、句子事件与平台组装边界

[English](001-state-events-and-runtime-boundaries.md)

日期：2026-10-22。状态：采用。

## 背景

历史记录曾从最多十行的字幕快照识别完成句子；慢翻译使被裁剪的旧句子无法进入历史。UI 直接修改设置，并在绘制后保存，导致后台或无窗口操作缺少一致的保存及词表更新。引擎路径查找又经资源包依赖 MyGo，让无界面工具承担桌面依赖。

## 决策

1. 显示快照和完整句子生命周期分别输出。`OnLine` 事件包含整句，完成事件涵盖成功、跳过和取消；历史和评测以它为记录来源。
2. UI 读取独立副本，通过应用命令提交。命令负责派生状态和持久化；绘制不保存，成功写入才确认 saved 状态。
3. 功能先在 `core` 内形成拥有状态与行为的服务，`Core` 保留协调入口。只有复用或依赖方向需要时才新增包。
4. 桌面入口解析资源路径并注入；`resource`、`engine`、`provider` 不认识 MyGo。benchmark 和桌面共用 provider 构造，配置来源各自保留。
5. 每个后台任务属于根 context，并有替换、取消和迟到回调策略。主线程调度不阻塞生产者，关闭时拒绝新工作。
6. 通用控件留在 `ui/kit`，业务呈现和导航契约放 `ui/shared`，窗口组装归 `ui/shell`。
7. 使用共享 JSON fixtures 约束三个协议实现，保留 wire protocol v1；暂不增加跨语言代码生成或额外 Go module。

## 影响与取舍

完整事件需要消费者快速返回，并由顺序记录者处理乱序完成；这增加少量缓冲状态，但避免数据正确性受显示容量影响。UI 草稿需要显式提交，并对菜单等延迟回调单独调用命令。保留 Core 的协调入口减轻迁移成本，包边界检查和 UI 可变字段检查防止重新引入直接依赖。

设置和场景仍使用现有 JSON 文件。原子替换减少部分写入风险，失败保留脏状态；它不构成跨多个文件的事务。签名、真实设备权限、实际模型质量由发布前人工验证承担。

## 证据

- `app/internal/live/lifecycle_test.go`：积压、溢出、取消、事件完整性。
- `app/internal/core/*_test.go`：保存失败重试、词表更新和任务取消。
- `app/internal/ui/settings/state_test.go`：绘制结束后的原生菜单提交。
- `app/layers_test.go`：包族依赖与 UI 状态入口规则。
- `protocol/fixtures.json`、两个 Go module 的契约测试、Swift 验证器。
- `scripts/check.sh` 和 `scripts/test.sh`：本地和 CI 共用的检查与测试。
