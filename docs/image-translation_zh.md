# 图片翻译

[English](image-translation.md)

## 目标

字幕只能翻译听到的话。游戏对话框、视频里的招牌和字幕条、直播间的聊天，这些都没有声音。用户按一个快捷键，就能看到屏幕上一块区域的译文。Index-Translate 全系列（2B / 9B / 35B）原生支持图片输入，不用另接 OCR：图片和提示词一起发过去，直接返回译文。

## 设计决定

| 项 | 决定 |
|---|---|
| 截哪里 | 框选的一块区域，不截全屏。实验里只框对话框最快、最准；截全屏会混进状态栏和菜单，还会重复输出 |
| 权限 | 默认不需要新权限：翻译剪贴板里的截图。一键框选是可选的，要用户自己去系统设置开「屏幕录制」 |
| 翻译 | 单独的引擎，在 识别与翻译 › 图片翻译 里从能读图片的引擎中选，带上当前场景的整张对照表（[翻译场景](scenes_zh.md)），实验里名字靠它译对。见[用哪个引擎](#用哪个引擎) |
| 结果 | 浮动卡片：原图缩略图在上，译文在下，用 MyGo 的 `markdown.Stream` 流式显示（匀速、逐字、淡入），按 GitHub 风格的 Markdown 渲染（模型翻译网页截图时会输出 Markdown），单个换行也保留，因为游戏对话通常一人一行；可以复制，按 Esc 或右上角关闭 |
| 保存 | 图片和译文都不存。统计只记翻译成功的张数，按天记在翻译它的引擎名下，从不记内容 |
| 快捷键 | 默认 ⌥⇧S（`prefs.ImageShortcut`），可以自定义，不能和开始 / 停止翻译的快捷键相同。菜单栏面板的「截图翻译」按钮效果一样 |
| 自动识别 | 不做：每隔一会儿截一次屏、有变化就翻译，更费流量，误翻也多 |

## 怎么拿到图片

macOS 上，一个应用要读取**其他应用窗口的画面**，必须先有「屏幕录制」权限。系统自带的截图（⌃⇧⌘4）不受这个限制。实测：由 Tomoru 启动的系统截图（`screencapture -i`、`-R`）都算在 Tomoru 头上，没有权限时松开鼠标就弹出权限请求，拒绝后什么都截不到。系统的窗口选取器 `SCContentSharingPicker` 不需要权限，但它是给共享屏幕用的，只能选整个窗口，用起来不像截图，所以没有采用。

所以有两种方式：

| 方式 | 权限 | 做法 |
|---|---|---|
| **剪贴板**（默认） | 不需要 | 用户先用 ⌃⇧⌘4 截到剪贴板，再按 ⌥⇧S。读剪贴板用 `mygo.Clipboard.ReadImage()`，它会把 TIFF 转成 PNG |
| **一键框选**（可选） | 屏幕录制 | 按 ⌥⇧S 直接框选，框完就翻译；按 Esc 取消。框选都走引擎的 `select`（`internal/capture`）：macOS 上它运行系统的 `screencapture -i -x`，并在它运行时看鼠标左键按下、松开的位置，报告选区；Windows 上是引擎自己的框选窗口。截图存在临时目录，读完就删 |

一键框选在首次引导里是可以跳过的一步：先问要不要；要的话去系统设置打开 Tomoru 的屏幕录制，然后选快捷键，按它框右边的示例对话（`assets/samples/`，由 `guide/samples_test.go` 生成）试一下。

- macOS 只给「打开系统设置」，没法在应用里一键允许。开完以后系统问「退出并重新打开」时可以点「稍后」：权限检查和截图都在每次新起的引擎子进程里，不用重开就能用。重开的话，引导回到停下的那一步。
- 权限的查询和申请在引擎里（`screen-access`、`request-screen-access`，见[引擎协议](engine-protocol_zh.md)）：引擎是 Tomoru 启动的子进程，系统把它算作 Tomoru。开着相关界面时每 3 秒查一次；框选失败（比如在系统设置里关掉了）时马上再查一次。
- 第一次框选时，macOS 会再确认一次，之后还会定期确认。这是系统对屏幕录制的规定。
- 不开框选的话，⌥⇧S 照旧翻译剪贴板里的截图，功能不会没有。

Tomoru 的字幕层在录屏时隐藏（可选，`sharingType = none`），不会出现在截图里。

## 用哪个引擎

图片有自己的引擎（`Preferences.ImageMT`），和字幕的（`Preferences.MT`）分开：有些引擎不能读图片，比如用户接的大多数纯文本接口。它总是明确选的，在 识别与翻译 › 图片翻译 里，菜单只列出现在能读图片的引擎（`Core.ImageEngines`）：云端的 Index-Translate 35B（默认）、下载好的本机 2B 和 9B、用户的接口（测试发现不能读图片的除外）。选的是云端引擎时，下面一行说明这个服务会收到画面。图片的快捷键也在这一组里，偏好设置里照旧有。

- **旧设置**：`ImageMT` 为空时，启动时设一次：`MT` 能读图片（本机模型、没发现不能读图片的接口）就用它，否则用云端。首次引导里选翻译引擎时，能读图片的也一起用来翻译图片。
- **测试接口**：添加/编辑接口对话框的「测试」在示例句子之外，同时发一张这句话的小图（`testPicture`）。句子译回来后，看图片的结果判断能不能读图片：译出来了就能；返回错误状态码（DeepSeek 是 400，没有视觉投影的 llama-server 是 500；429 除外）就不能；其他情况算不知道。结果显示在译文下面（能读图片 / 不能读图片），记在接口上（`Endpoint.Vision`）：接口已保存且测的是同一个接口时立即记下，否则保存时记下。改了地址、模型或提示词格式就又算不知道。以前保存的接口在测试发现不能读图片之前一直列着。
- **没了**：选来翻译图片的模型被删除、接口被删除或测出不能读图片时，改用云端，和字幕翻译用 `Successor` 一样；撤销删除接口会把它选回来。测试测出来时，结果下面会说图片已改用云端（`TestResult.ToCloud`）。
- **只用选的那个**（`EngineService.imageEndpoint`）：图片从不发给别的引擎。选的引擎翻译不了时（模型没下载、模型正在移动、接口失败），卡片上说明原因。

| 引擎 | 图片 |
|---|---|
| Index-Translate 云端 | 照旧。正常约 2 秒开始出字；10 秒还没出字时，换一条新连接重新请求一次（`Endpoint.ImageWait`）：经过代理时，到它的连接有时收下图片后一直不回应，直到几分钟后服务器关掉连接，而 HTTP/2 会把重新请求的图片又发到这条连接上（2026-11-01）。新连接也不回应时，卡片像字幕那样说明 |
| 本机模型（2B / 9B） | llama-server 加上模型的视觉投影文件（`--mmproj`，Q8_0：2B 345 MB、9B 592 MB，同一个仓库）来看图。它是模型的文件之一（`models.Model.Vision`），跟模型一起下载、一起删除，所以本机模型总能看图。llama-server 只在第一张图片时才加载它（`Server.EnsureVision`）：它让 2B 多占 430 MB 内存、9B 多占 680 MB，只翻字幕用不着。正在翻译字幕时就带上它在同一个端口重启，字幕的翻译器地址不变（第一张图约 2 秒，之后 0.6 秒），之后一直带着。字幕没在用本机模型翻译时，为图片启动的 llama-server 在卡片关闭时停掉 |
| 另一个本机模型正在翻译字幕时的本机模型 | 失败，返回 `ErrModelBusy`，卡片上说明：llama-server 一次只运行一个模型，换成另一个会停掉字幕的 |
| 用户自己接的接口 | 把图片发给它；失败了（可能不支持看图），卡片上会说明，并附上接口的报错。不改用别的引擎：图片只发给用户选的服务 |

本机实测（M 系列 Mac，2026-10-28）：首次引导里的日文对话（1040 × 360，390 个 token），模型加载好以后 2B 用 0.9 秒、9B 用 2.7 秒，名字都对。本机模型的图片最长边限制在 1280 像素（`provider.LocalImageSide`）：llama-server 的 4096 个 token 上下文由几个槽共用，一张 2048 像素的截图就占了 2971 个，接着的下一张图直接让它崩了。2B 译成英文时偶尔只会一行接一行地重复一个名字，直到 token 用完（15–27 秒）；同一行连续出现三次就在那里结束。

## 翻译请求

`translate/image.go`：

- **格式**：OpenAI 多模态格式，同一条消息里放一段文字和一张 `image_url`（base64 data URL）。
- **图片大小**：Index 建议最长边 512–2048 像素，超过 2048（本机模型是 1280）就用 CatmullRom 缩小。Retina 屏截的图是 2 倍，框 600 点宽就是 1200 像素，一般不用缩。最长边不到 1000 像素就放大 2 到 3 倍：100% 缩放的屏幕（Windows 上常见）文字只有 12 像素左右高，模型会漏词、韩语认错、中文重复一行，放大一倍就读对了。
- **提示词**：`请将图片中的文本翻译为<目标语言>，直接输出翻译结果。`。当前场景有对照表时，改用 instTrans 格式，在【约束要求】里加 `【硬性要求】专名/术语对照: A→B、C→D`，和字幕翻译的写法一样。字幕翻译只带和这一句相关的条目；图片里有哪些专名事先不知道，所以带上场景的整张对照表。图片翻译一次只发一个请求，提示词长一点没关系。
- **源语言**：不用指定，图片里可能混着几种语言。目标语言默认跟字幕的目标语言一致，也可以在卡片右上角另选（`prefs.ImageTgt`）：选了会把当前图片重新翻译一遍，之后的图片也用它，字幕的语言不变、也不会重启；再选回字幕的语言，就重新跟着字幕走。场景对照表只在和字幕同一种目标语言时带上，因为表里的译名是那种语言的。
- **整理输出**：去掉连续重复的行（实验里两次出现整行重复），流式时也去；同一行连续出现三次就结束。

状态在 `core/image.go`（`ImageService`），关掉卡片会取消还没回来的请求。

## 卡片

`ui/imagecard/`：MyGo 的 Panel 窗口，浮在所有应用上面，在 macOS 上不激活 Tomoru 也能拿到键盘。

- **位置**：出现在框选区域下方、左边对齐，下面放不下就放到上方；从剪贴板来的、或 macOS 上按空格点选窗口的，放在菜单栏图标（任务栏图标）旁边。拖标题栏可以移动，点外面不关闭。
- **大小**：默认宽 440，高度按缩略图加四行译文算（`imagecard.FitHeight`），最高 440，所以一条对话框截图打开的是矮卡片；用户可以拖边缘调整（最小 340 × 300），记住调整后的大小（`prefs.ImageW`、`ImageH`），之后的卡片都按这个大小打开、不再按图片算高度，超出屏幕时缩到放得下。卡片显示以后自己从不改大小：译文比卡片长就在里面滚动，流式输出时自动跟到最后，用户往上滚了就不跟。原来卡片随译文长高，每多一行都会先闪一帧被截短的卡片，窗口才跟上。
- **内容**：原图缩略图、译文（流式显示；出来之前是三条呼吸的占位线），以及「复制」。原图要一起显示：实验里数字会译错（49980 变成 49800），用户可以对照着看。点缩略图会弹出一个单独的窗口显示完整原图，放在屏幕中间，按它在屏幕上的大小（放不下就缩到屏幕的九成，不裁切）。拖图片可以移动，拖边缘可以调整大小，图片跟着缩放；点关闭按钮（半透明的圆，鼠标移到图片上才出现，移到它上面变红）或按 Esc 关闭，关掉卡片时也一起关闭。
- **底部**：谁翻译的，即图片选的引擎，「由 Index-Translate 云端翻译」（或在本机、或用户自己的接口），Index-Translate 是链接；悬停提示图片和译文都不保存。
- **没有图片**：没开屏幕录制、剪贴板里也没有图片时，直接提示开启屏幕录制，和首次引导一样（开启；被拒绝过就打开系统设置）；开好之后显示「截图翻译」按钮，点了直接框选。

## 测试

- 请求的组装：有无对照表时的提示词、缩图、data URL；用 httptest 假装 Index 接口，测流式输出和去重。
- 引擎（`core/image_engine_test.go`）：旧设置、引导里的选择、菜单（没有纯文本接口、没有没下载的模型）、图片只发给选的引擎、本机模型被占用、测试接口能不能读图片、删除。
- 卡片：Tester 测权限的几种状态、流式显示、复制、切换语言、Esc 关闭、错误显示；对话框截图和整页截图的高度、等待状态、完整原图；原图窗口的位置和大小（`pictureBounds`）。
- 手动：在没有屏幕录制权限的打包版里测框选和权限申请（开发机的终端通常已经有这个权限，测不出来）。测完可以用 `tccutil reset ScreenCapture dev.acane.tomoru` 恢复到没问过的状态。

## 实验（2026-10-20）

Index 云端 35B，`enable_thinking: false`，流式。图片用无头 Chrome 渲染。

| 图 | 首字 | 全部 | 结果 |
|---|---|---|---|
| 日文游戏全屏（对话框 + 选项菜单 + 状态栏），1280×720 | 0.34 s | 1.19 s | 通顺，但漏了说话人名字，クロード 译成「克洛德」 |
| 同上，加对照表（クロード→克劳德、エルナ→艾露娜、星の欠片→星之碎片） | 0.32 s | 1.21 s | 名字都按对照表译对了，带上了说话人；但状态栏那一行重复输出了两遍 |
| 只框对话框，1120×170 | 0.24 s | **0.50 s** | 最干净：「埃尔娜：克劳德。那座塔顶上发光的东西，该不会就是“星之碎片”吧？……」 |
| 日文新闻网页，1280×800 | 0.31 s | 3.40 s | 整体很好；「4万9980円」译成 49800 日元，「来春」译成「春季」 |
| 韩文直播页（聊天区），1000×640 | 0.29 s | 1.40 s | 「도배하면 차단됩니다」（刷屏会被封禁）译错成「如果帮忙的话，我会拉黑你」；平台名「치지직」只译了一半；最后一行重复 |

在 app 里实测（日文对话框 1120×340）：首字约 0.5 秒，全部 1.3–1.9 秒；不带对照表时人名译成「克洛德」「埃尔娜」，带上后译成「克劳德」「艾露娜」，数字 49,980 没有错。

结论：

- 框一小块不到 1 秒就能看完，整页网页 3 秒多；
- 对照表在图片翻译里一样有效；
- 截得越多，越容易出现重复行和漏译，所以要框选；
- 数字和网络用语偶尔会错，卡片上要同时显示原图。
